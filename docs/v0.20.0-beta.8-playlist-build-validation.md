# v0.20.0 Beta 8 Playlist Build and Async Reconstruction Validation

## Scope

This beta corrects model-created playlist discovery, partial completion,
version-family classification, first-publication constraints and playlist
reconstruction feedback.

## Contract

- Roon discovery supplies exact playable candidates; MusicBrainz remains the
  authority for recording identity and canonical metadata.
- A fresh compatible Roon `result_id` is reused without another search but
  never bypasses MusicBrainz or strict title, credit and version validation.
- `recording_intent` describes a recording version, not a genre. Ordinary dub
  titles are standard; explicit `Dub Mix` or `Dub Version` qualifiers are dub.
- `release_year_from` and `release_year_to` validate the MusicBrainz
  first-publication year.
- Three failed replenishment rounds save every verified track and report
  `added_count`, `missing_count` and `complete:false`. Zero verified tracks
  still fail without creating an empty playlist.
- `rejection_summary` aggregates complete failure counts and recovery actions;
  only the latest 25 individual rejections are returned to keep MCP payloads
  bounded.
- Reconstruction is an asynchronous, idempotent-per-playlist job with
  MusicBrainz, Roon binding and metadata phases.

## Removed surface

The migration is complete; no compatibility endpoints remain for:

- `/virtual-playlists/*`
- `/playlists/:playlist_id/resolve`
- `/playlists/:playlist_id/metadata/refresh`
- `/media/images/:image_key`

The canonical surface is `/playlists/*`, `/roon/images/*` and the single
`roon_rebuild_playlist` MCP intent.

## Automated validation

Run:

```powershell
pnpm run test
pnpm run build
```

Coverage includes partial persistence, structured rejection summaries,
MusicBrainz publication-year constraints, exact Roon reference reuse, dub
genre/version separation, asynchronous reconstruction progress, active-job
deduplication, MCP schemas and portal polling.

## Post-deployment validation

1. Refresh the ChatGPT app and start a new conversation.
2. Confirm `tools/list` exposes the beta 8 schemas and only
   `roon_rebuild_playlist` for reconstruction.
3. Create a constrained niche playlist and verify exact Roon-derived
   candidates, MusicBrainz metadata and an explicit partial summary if needed.
4. Start reconstruction from the portal and confirm immediate progress,
   terminal report and preserved song selection/order.
