# v0.20.0 Beta 16 Official Audio and Exact-Version Validation

## Purpose

Beta 16 closes the gap between synthetic recording-resolution tests and real
playlist requests generated by an LLM from ordinary human prompts. It focuses
on exact remixes, alternate versions and live performances, where a plausible
title is not sufficient evidence of the intended audio recording.

MusicBrainz remains the source of truth for recording identity and metadata.
ListenBrainz is optional supporting evidence for selecting a unique
release-specific MusicBrainz recording. Roon only supplies the playable
binding.

## MCP candidate-generation contract

The model-visible playlist instructions and schema now require:

- 125% of the target for standard lists, 160% for constrained lists and 200%
  for exact-version lists;
- official published titles and one structured credit for every actual named
  collaborator;
- native-script titles and artist names for non-Latin catalogs when known;
- an actual official audio album or digital audio single for live, remix and
  acoustic versions;
- exclusion of concert films, video albums, DVDs, Blu-rays and video-only
  releases unless the same performance has a separately published audio
  edition;
- no invented live, venue, date or remix suffixes;
- ordinary dub music and naturally acoustic songs to remain `standard` unless
  a separately named recording version was requested.

Requests for a playlist remain permanent by default. The temporary playlist
tool remains reserved for immediate playback commands where the user did not
ask to create a visible playlist.

## Recording identity changes

- MusicBrainz video recordings are rejected both during stored-MBID
  revalidation and candidate ranking.
- A ListenBrainz video identity cannot displace a compatible audio recording.
- A unique release-specific ListenBrainz mapping can disambiguate otherwise
  equivalent MusicBrainz recordings, but cannot bypass title, artist, release
  or version compatibility.
- Collective artist credits such as an artist with their established backing
  group are treated as equivalent only through explicit normalized evidence.
- Letter-spaced release titles and harmless edition punctuation are normalized.
- Unrelated compilation titles no longer manufacture version evidence.
- A sparse duplicate on the same exact live release cannot outweigh a
  documented compatible recording.

The persistent recording-resolution cache namespace advances to `v18` so
earlier ambiguous and video-derived decisions are revalidated.

## Roon binding changes

- Reconciliation retains up to twelve candidates so a later verified result
  is not lost behind several plausible entries.
- A high-confidence title match may bind when the canonical performer is among
  Roon's linked credits rather than only its display lead.
- An exact live performance may use MusicBrainz location evidence to match a
  venue contained in the Roon title.
- Canonical live suffix handling recognizes album-style titles such as
  `Homecoming Live`.
- A result from another concert, or a generic `Live` result with no performance
  anchor, remains rejected.

## Configuration and local validation

`ROON_CORE_HOST` and `ROON_CORE_PORT` provide an optional direct Core
connection for routed or VLAN environments where multicast discovery cannot
cross the network boundary. They must be configured together. Discovery
remains the default when both values are absent.

The repository includes isolated start and stop scripts for local validation.
They use a separate extension identity and data directory, avoiding changes to
the deployed RoonIA instance.

## Real LLM validation

The final frozen cohorts were generated by `gpt-5.6-sol` from human-style
requests and the current MCP contract. Candidates were not manually repaired.

| Case | Scenario | Proposed | Accepted | Consumed | Backend time |
| --- | --- | ---: | ---: | ---: | ---: |
| R07 | Known remixes and alternate versions | 227 | 99/100 | 227 | 543.4 s |
| R08 | Exact live concert recordings | 200 | 100/100 | 170 | 358.1 s |

The remaining R07 position coincided with a transient MusicBrainz provider
failure. Repeating the affected candidates unchanged recovered `Situation
(1982 U.S Remix)` as the intended audio recording and bound it to Roon. The
frozen pool therefore contains at least 100 valid playable candidates.

A subsequent complete warm R07 confirmation could not start because the
direct Core endpoint became unavailable. The runner stopped before processing
any candidate, so it produced no contrary matching result.

Focused evidence:

- 44 of 46 previously ambiguous live recordings resolved exactly after the
  release-specific evidence change; the remaining two stayed conflicts.
- Six of nine difficult live bindings resolved, up from zero, without
  accepting a different concert.
- Twelve of 28 prior video-derived failures recovered as official audio
  recordings; video-only identities remained rejected.
- A low-reasoning generation trial was discarded because it produced more
  album noise, provider requests and exact video proposals.

The complete incremental experiment record is stored under
`validation/llm-real-playlists/`.

## Release gate

- Complete automated suite: 333 passed, 0 failed.
- TypeScript production build: passed.
- `git diff --check`: passed.

Beta 16 is suitable for deployment validation. Exact-version playlists of 100
tracks still require roughly six to nine minutes of backend work, in addition
to model candidate generation. This is acceptable for a beta but remains the
primary optimization target before the feature is considered final.
