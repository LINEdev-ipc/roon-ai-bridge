# v0.20.0 Beta 11 Canonical Binding and Provider Scheduling Validation

## Why this beta exists

The real Beta 10 P01 pilot saved 92 of 100 tracks in 352,908 ms. Read-only
inspection of all rejected bindings found correct Roon catalog results that
were discarded because their visible titles contained tempo annotations,
mastering labels or a canonical mix name. Other candidates returned several
equivalent sparse Roon editions without album or duration data.

The timing trace also showed that the MusicBrainz limiter serialized the full
request lifecycle. A slow response therefore blocked every unrelated lookup
behind it. ListenBrainz is advisory but could remain on the critical path for
up to 12 seconds.

## Corrective design

- MusicBrainz request starts remain globally spaced by the configured minimum
  interval, while in-flight responses may overlap. Retries acquire a new
  request slot and retain the existing bounded retry policy.
- ListenBrainz remains an optional candidate and agreement source, with a
  two-second critical-path timeout.
- Title equivalence ignores terminal numeric tempo annotations and recognizes
  `remastering` as an edition label.
- A standard request accepts a canonical MusicBrainz title that itself names a
  mix, remix or rework. It still rejects an unsolicited alternate version.
- A high-confidence direct Roon match may bind after the strict title, credit
  and version gates. Multiple results are collapsed only when all are sparse
  editions with no album and identical visible credits; materially different
  editions remain ambiguous.

MusicBrainz remains the identity and metadata authority. These rules only
decide which Roon catalog object plays the already-established canonical
recording.

## Validation corpus

The incremental `validation/playlist-e2e-beta9` harness still contains ten
human-style prompts and 1,430 candidates without embedded MusicBrainz IDs.
Ordinary playlists now contain only standard recordings across both primary
and reserve candidates. Exact remix, live and acoustic prompts retain the
requested recording family. Fixture generation fails instead of silently
filling an ordinary pool with incompatible versions.

## Automated gate

Before deployment:

- the complete test suite and TypeScript build must pass;
- the fixture audit must report 10 playlists, 1,430 candidates, no embedded
  MusicBrainz IDs and no wrong-intent candidates;
- focused tests must cover overlapping MusicBrainz responses, canonical mix
  titles, tempo and mastering annotations, equivalent sparse editions, and
  preservation of genuine ambiguity.

Result on 2026-07-28:

- 296 tests passed, 0 failed;
- TypeScript build passed;
- fixture audit passed for 10 playlists and 1,430 candidates;
- P01-P05 and P09-P10 contain only standard recording intent;
- P06-P08 contain only their requested remix, live, acoustic or cover intent;
- no fixture candidate contains an embedded MusicBrainz recording ID.

## Real Roon gate

After Beta 11 is deployed, repeat P01 first with diagnostics enabled and no
playback. It must save 100 of 100 tracks and materially improve the Beta 10
wall-clock time of 352,908 ms without relaxing credit or requested-version
correctness. Only then run P02 through P10.
