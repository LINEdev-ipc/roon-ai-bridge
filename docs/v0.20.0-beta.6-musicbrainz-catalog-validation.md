# v0.20.0 Beta 6 MusicBrainz Catalog and Roon Binding Validation

## Scope

Beta 6 activates the identity model that previous v0.20 betas exercised in
read-only diagnostics. New automatic playlist candidates now follow this
contract:

1. Resolve the requested recording in MusicBrainz.
2. Continue only when the recording identity is exact and compatible with the
   requested standard, live, remix, dub, acoustic, cover or alternate intent.
3. Search Roon with the canonical MusicBrainz title and artist credit.
4. Bind only a playable Roon result that passes the strict recording and
   performance checks.
5. Send ambiguous MusicBrainz results or unproved Roon matches to the existing
   manual selection workflow.

The binding is an observation, not a second source of catalog truth. It stores
the temporary Roon item and result references, source, canonical query,
playability, selection origin and verification time. It is deliberately marked
`reusable=false`; a later playback still has to resolve the item safely through
Roon.

## Stored catalog model

The SQLite migration `004_music_catalog` adds normalized tables for:

- recordings and ordered artist credits;
- works, ISWCs and recording/work relations;
- composers, lyricists, writers and arrangers;
- release groups and their relationship to a recording;
- an exact release and release track only when available evidence identifies
  one edition;
- ISRCs, genres and genre vote counts;
- Cover Art Archive image references;
- independent Roon recording bindings.

MusicBrainz is authoritative for catalog identity and descriptive metadata.
Roon remains authoritative for availability, source, playable object and
current library/streaming observation. Cover Art Archive is used for a
MusicBrainz-linked cover when available; the normal Roon artwork remains the
fallback. Provider responses and cover lookups use the persistent metadata
cache.

## Visible song metadata

The ChatGPT track widget advances from `ui://roonia/widget-v19/*` to
`ui://roonia/widget-v20/*`. Track cards in the widget and portal may display:

- canonical title, joined artist credit, version/disambiguation and duration;
- MusicBrainz recording ID and ISRCs;
- work title/type/language and ISWCs;
- composers and lyricists;
- genres;
- canonical release group, first-release year and primary/secondary type;
- exact edition, label, barcode, medium, disc and track position when verified;
- the selected Roon source and binding status;
- MusicBrainz-linked cover art, with Roon artwork as fallback.

Missing data is omitted rather than inferred. A release group is the normalized
album identity; country-specific releases do not create duplicated song
identities. An exact edition is stored only when Roon or explicit evidence
narrows the candidates safely.

## Automated validation

Run locally:

```powershell
pnpm run test
pnpm run build
node --check portal/app.js
```

Focused coverage confirms:

- an exact MusicBrainz identity is resolved before the first Roon search;
- the Roon query and strict gate use canonical title and artist credit;
- ambiguous MusicBrainz candidates do not trigger an automatic Roon search;
- canonical entities and the Roon binding are persisted separately;
- the binding is non-reusable and records whether it was automatic or manual;
- exact release-track duration and cover references retain their provenance;
- database creation and legacy migration both create the catalog model;
- widget v20 exposes the canonical metadata and independent Roon binding.

## Deployment validation

After an explicit beta deployment:

1. Confirm the deployed commit matches `origin/beta`, and that
   `package.json`, MCP initialization and `/roon/status` report
   `0.20.0-beta.6`.
2. Confirm `tools/list` exposes the expected schemas and
   `ui://roonia/widget-v20/*` resources.
3. Refresh the ChatGPT app and start a new conversation so the tool and widget
   cache is replaced.
4. Build a representative playlist containing a standard studio recording, a
   named remix, a live version, a collaboration, a non-Latin title and a song
   with many country editions.
5. Verify each accepted entry has a MusicBrainz recording ID and that the Roon
   result is playable. Ambiguous identities must appear as manual-required
   omissions, not guessed selections.
6. Complete one omission through the existing manual Roon search. Verify the
   chosen track is added, enriched and stored with
   `selection_origin=manual`.
7. Open individual song cards in ChatGPT and the portal. Confirm available
   canonical credits, work, genres, release group, exact edition and identifiers
   are visible, and missing fields do not render empty placeholders.
8. Verify a Cover Art Archive image loads when present and Roon artwork still
   renders when it is absent.
9. Play an accepted track in Despacho through the normal MCP tool and confirm
   the final now-playing state matches the selected recording.
10. Repeat the playlist request to confirm persistent cache hits reduce provider
    requests without reusing a stale Roon browse reference.
