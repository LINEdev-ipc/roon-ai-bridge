# v0.20.0 Beta 13 Release-Anchored Binding Validation

## Why this beta exists

The deployed Beta 12 P06-P09 gate accepted 301 of 400 requested tracks. It
improved remixes and covers, but accepted no acoustic candidate, regressed the
live case slightly and bound at least one Nina Simone request to a different
concert.

The real artifacts and read-only Roon searches established five independent
causes:

- version-specific MusicBrainz discovery did not include `album_hint` in the
  search query;
- a supplied album remained soft evidence, allowing another live recording to
  win;
- Roon release navigation was skipped whenever MusicBrainz identity was
  already available;
- acoustic discovery was forced through studio ranking even though Roon
  classifies real unplugged tracks as live or alternate;
- base-title normalization was case-sensitive and did not normalize `En Vivo`,
  producing false low-confidence results.

Roon searches also used every canonical artist-credit entry. Roon commonly
shows songwriters and other contributors in that field, so requiring all of
them reduced binding confidence even when the requested performer was present.

## Corrective design

MusicBrainz remains the recording authority. Exact recording families now:

- include the observed release in the MusicBrainz query;
- require the selected MusicBrainz recording to occur on a compatible release;
- verify the same release rule when a stored recording MBID is enriched;
- use the `v8` recording-resolution cache namespace so Beta 12 decisions
  cannot mask the new semantics.

Roon remains the playback binding. The binder now:

- treats acoustic Roon classification as unknown during discovery so studio,
  live and alternate representations remain eligible;
- verifies Roon release evidence for exact recording families even when a
  canonical MusicBrainz profile already exists;
- accepts an exact-family binding only with compatible album, shared ISRC or
  another family-specific canonical anchor;
- keeps a plain live or acoustic title album-anchored instead of accepting any
  performance with the same base title;
- searches with the requested performer, or the equivalent canonical credit,
  instead of concatenating every MusicBrainz artist-credit entry;
- normalizes live, concert, `En Vivo`, direct, unplugged, acoustic, refix and
  related suffixes case-insensitively;
- avoids a duplicate canonical Roon search when the speculative query already
  used the same title and performer;
- reuses release hydration within one candidate-resolution stage.

Ordinary studio recordings retain the existing edition-insensitive fast path.

## Automated evidence

Focused regressions cover:

- Shakira `Inevitable`, where Roon exposes the unplugged recording as live;
- The Corrs `What Can I Do`, where Roon exposes the unplugged recording as
  alternate;
- Nina Simone `The Other Woman`, rejecting the 1964/1985 alternatives and
  selecting the requested Town Hall performance;
- release-constrained MusicBrainz discovery refusing an incompatible concert;
- canonical metadata plus explicit Roon release verification;
- neutral Roon version discovery without filtering live or alternate acoustic
  candidates;
- preservation of the requested performer when canonical credits contain
  additional contributors.

Local release validation completed successfully:

- complete automated suite: 306 passed, 0 failed;
- TypeScript production build: passed;
- fixture generation: passed;
- fixture audit: 10 playlists and 1,505 candidates;
- exact-version coverage: P06 has 160 remixes, P07 has 160 live recordings,
  and P08 has 71 acoustic recordings plus 89 covers;
- no MusicBrainz recording or release identifiers are embedded in the
  fixtures.

After deployment, preserve the Beta 12 artifacts and run P06, P07 and P08
first without playback. P09 must then remain 100/100. Only when all four cases
reach their target with no wrong performance should P01-P10 be rerun.
