# v0.20.0 Beta 10 Playlist Identity Fast Path Validation

## Why this beta exists

The first real Beta 9 pilot used the ordinary prompt "Crea una playlist de 100
canciones de electrónica con bajos potentes." It saved only 67 of 100 tracks
and took 625,701 ms. The run made 272 MusicBrainz requests, 207 ListenBrainz
requests and 179 Roon searches. The complete rejection diagnostics reported:

- 19 transient MusicBrainz provider failures;
- 20 MusicBrainz identities not found;
- 17 Roon bindings that remained unresolved;
- 2 duplicate proposals.

The fixture also mixed exact versions into an ordinary playlist. That made the
pilot stricter than the human prompt and hid the difference between standard
recording discovery and explicit remix/live/acoustic requests.

## Corrective design

Playlist construction now has two metadata phases:

1. The critical path performs a MusicBrainz recording search and uses the
   selected search result to establish canonical recording identity.
2. Roon discovery runs concurrently and binds any title/credit/version match
   whose MusicBrainz ISRC or duration proves that different Roon editions
   contain the same recording.
3. The playable playlist is saved as soon as the target or candidate pool is
   exhausted.
4. Work credits, genres and other full MusicBrainz metadata are retrieved in
   the background and merged into the saved tracks.

The identity phase therefore avoids recording-detail, work-detail and
release-track requests in the user-facing creation latency. MusicBrainz
network and timeout errors are retried with bounded exponential backoff. Exact
version searches retry with the core title when MusicBrainz does not index the
supplied remix, edit, live-session or version label as part of the title.

## Validation corpus

`validation/playlist-e2e-beta9` remains the incremental 10-playlist harness so
the authorized isolated Roon extension and earlier evidence can be reused.
Its generated fixtures contain 1,430 candidates and no MusicBrainz IDs.

- Ordinary prompts put standard recordings first and keep alternate versions
  out of their first 100 proposals.
- Remix, live and acoustic prompts retain exact-version recording intent.
- The runner disables background enrichment so it measures only the time until
  the playable playlist is saved.
- Diagnostic runs retain every rejection and per-candidate timing while the
  normal MCP response remains bounded.

## Real Roon gate

Beta 10 is locally validated but not accepted for deployment until the same
P01 pilot is repeated against the deployed container. The gate is:

- materially better than the Beta 9 baseline of 67/100 and 625,701 ms;
- no regression in standard-versus-exact-version selection;
- complete rejection and provider timing evidence retained.

Only after P01 passes should the remaining nine 100-track playlists run. No
validation step starts playback or changes a Roon zone.
